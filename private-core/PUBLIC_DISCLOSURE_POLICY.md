# Public Disclosure Policy

Deep Analytica uses progressive disclosure for product, research and technical material.

## P0 — PUBLIC
Positioning, customer pain, use cases, high-level workflow, selected UI, public product concepts.

## P1 — PUBLIC EVIDENCE
Selected research, benchmarks, demonstrations and evidence necessary to evaluate capability.

## P2 — QUALIFIED ACCESS
Selected system architecture, integration patterns, deployment topology, security principles and commercial implementation detail for identified leads/partners.

## P3 — DUE DILIGENCE
Expanded technical review for enterprise clients, investors, research partners and strategic counterparties under an appropriate controlled process.

## P4 — INTERNAL
Runtime implementation, internal policies, operational playbooks, sensitive infrastructure, private benchmarks and detailed evaluation logic.

## P5 — CROWN JEWEL
Proprietary control logic, evaluators, algorithms, model-routing intelligence, adversarial libraries, scoring/promotion logic and other know-how whose disclosure would materially reduce Deep Analytica's defensibility.

## Default
Detailed runtime, control logic and new system intelligence default to P4 unless explicitly reviewed and downgraded.

## Public communication rule
**Show the capability. Demonstrate the evidence. Protect the mechanism.**

## Historical limitation
Content previously made public should be treated as disclosed. Removing it from the current branch does not guarantee deletion from Git history, clones, forks, caches or third-party archives.
